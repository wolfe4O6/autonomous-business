# Product requirements

## Goals
An all-in-one desktop setup and monitoring experience for a bounded, autonomous business experiment. The operator chooses its business strategy within preauthorized constraints, runs without daily prompts, and provides evidence-backed daily reports.

## First launch
1. Ask where work should run: Linux VPS (recommended), another computer, or this computer.
2. Distinguish connecting an existing host from provisioning paid infrastructure. MVP connects an existing compatible VPS; provider-specific provisioning comes later.
3. Show requirements, install scope, and costs before host changes; pair securely.
4. Connect an AI API key through secure input and verify real inference. API inference does not require a local model or GPU.
5. Create/connect a dedicated inbox through a supported provider and verify inbound/outbound flow with owner-controlled addresses.
6. Connect publishing and payment accounts; complete legitimate user-owned identity verification.
7. Set budget, deadline, allowed activities, recurring-spend rules, and approval thresholds.
8. Run readiness checks and explicitly authorize Start.

No terminal work should be required in the finished supported setup paths. No silent administrator permission grants or invented identities. A model API key alone does not provision payment, hosting, or email accounts.

## Dashboard
Show current strategy, next task, verified artifacts, customers/orders, failures, blockers, total expenses, collected revenue, refunds, pending charges, remaining allowance, obligations, and net result. Separate donations/investment from customer revenue. Distinguish estimated API costs from reconciled charges.

## Owner controls
- Pause: prevent new work; expose in-flight actions.
- Intervene: pause, show evidence and current rationale, accept durable owner direction, invalidate conflicting queued work, replan, then explicitly resume.
- Stop Spending: prevent new spending authorizations regardless of agent state.
- Emergency Stop: revoke action access and halt execution where possible.

Remote state must distinguish requested, acknowledged, unreachable, and still-in-flight. Closing the desktop app must not stop a remote worker. Reconnecting must not create duplicate operators.

## Daily review
Report what shipped, what failed, actual costs and receipts, demand evidence, pending obligations, and tomorrow's hypothesis/limits. Allow waiting when no useful action is available. Report-generation failure must not fabricate results.

## Scope
Initial business envelope: legitimate digital products/services. Exclude speculative trading, borrowing, mass unsolicited outreach, hiring, and open-ended contracts. These are initial product safeguards, not a claim that a $200 experiment will be profitable.

## Open decisions
Product name/license; desktop framework; exact supported host matrix; AI/email/payment providers; secrets delivery and private connectivity; budget thresholds; backup retention. Resolve provider choices with capability proofs, not assumptions.
